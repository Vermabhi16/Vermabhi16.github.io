Data Lake Azure Databricks Leading FMCG Company

Enterprise Data Lake Platform

Designed and implemented a comprehensive enterprise data lake platform for a Fortune 500 FMCG company, consolidating data from 50+ source systems across manufacturing, supply chain, sales, and finance domains to enable advanced analytics and machine learning capabilities at scale.

01 Business Challenge

The organization faced significant challenges with siloed data across multiple business units, legacy on-premises systems, and inability to perform cross-functional analytics. Key pain points included:

  • Data scattered across 50+ source systems with no unified view
  • ETL processes taking 18+ hours for daily batch processing
  • No support for real-time analytics or machine learning workloads
  • High infrastructure costs with underutilized on-premises data centers
  • Limited data governance and lineage tracking capabilities
  • Inability to scale during peak business periods

02 Solution Architecture

Architected a modern lakehouse platform using Azure Data Lake Storage Gen2 as the foundation, with Databricks for data processing and Delta Lake for ACID-compliant storage. The solution implements the medallion architecture pattern for data organization and quality.

Key Architectural Decisions

  • Medallion architecture (Bronze/Silver/Gold) for incremental data quality improvement
  • Delta Lake for ACID transactions, time travel, and schema evolution
  • Unity Catalog for unified data governance across all workspaces
  • Auto Loader for scalable, incremental file ingestion
  • Structured Streaming for near-real-time processing requirements

03 Technical Implementation

Data Ingestion Framework

Built a metadata-driven ingestion framework using Azure Data Factory with parameterized pipelines that could onboard new data sources through configuration rather than code changes.

// Databricks Auto Loader Configuration 
spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "parquet")
    .option("cloudFiles.schemaLocation", schema_path)
    .option("cloudFiles.schemaEvolutionMode", "addNewColumns")
    .option("cloudFiles.inferColumnTypes", "true")
    .load(source_path)
    .writeStream
    .format("delta")
    .option("checkpointLocation", checkpoint_path)
    .option("mergeSchema", "true")
    .trigger(availableNow=True)
    .toTable(f"bronze.{table_name}")

Delta Lake Optimization

// Delta Table Optimization Strategy 
-- Z-Order clustering for query optimization
OPTIMIZE gold.sales_transactions
ZORDER BY (transaction_date, store_id, product_category);

-- Liquid clustering for automatic file management
ALTER TABLE gold.customer_360
CLUSTER BY (customer_segment, region);

-- Table maintenance automation
VACUUM gold.sales_transactions RETAIN 168 HOURS;

// Terraform - Databricks Workspace Configuration 
resource "azurerm_databricks_workspace" "main" {
  name                        = "dbw-${var.environment}-${var.project}"
  resource_group_name         = azurerm_resource_group.main.name
  location                    = azurerm_resource_group.main.location
  sku                         = "premium"
  managed_resource_group_name = "rg-dbw-managed-${var.environment}"

  custom_parameters {
    no_public_ip        = true
    virtual_network_id  = azurerm_virtual_network.main.id
    private_subnet_name = azurerm_subnet.private.name
    public_subnet_name  = azurerm_subnet.public.name
  }
}

06 Key Learnings

  • Early investment in data quality frameworks pays dividends throughout the platform lifecycle
  • Metadata-driven architectures significantly accelerate onboarding of new data sources
  • Unity Catalog provides essential governance capabilities but requires careful planning for migration
  • Autoscaling clusters with proper spot instance configuration can reduce costs by 60-70%
  • Delta Lake's time travel feature is invaluable for debugging and audit requirements
