Azure AWS Multi-Cloud Insurance Enterprise

Hybrid Multi-Cloud Data Platform

Architected a hybrid multi-cloud data platform spanning Azure, AWS, and on-premises data centers for a global insurance company. The solution enables unified data access, cross-cloud analytics, and regulatory compliance across 40 countries while optimizing costs and avoiding vendor lock-in.

01 Business Challenge

  • M&A activity resulted in data assets split between AWS and Azure cloud environments
  • Regulatory requirements mandating data residency in specific geographic regions
  • Legacy on-premises mainframe systems requiring integration with cloud analytics
  • Vendor lock-in concerns preventing full commitment to single cloud provider
  • Need for unified governance and security across all environments
  • Cross-cloud data movement costs impacting operational budgets

03 Technical Implementation

Cross-Cloud Data Access with Starburst

// Starburst - Federated Query Across Clouds 
-- Query joining Azure and AWS data sources seamlessly
SELECT
    c.customer_id,
    c.customer_name,
    c.region,
    p.policy_number,
    p.premium_amount,
    cl.claim_count,
    cl.total_claim_amount
FROM azure_delta.insurance.dim_customers c
JOIN aws_iceberg.policies.fct_policies p
    ON c.customer_id = p.customer_id
LEFT JOIN (
    SELECT customer_id, COUNT(*) as claim_count, SUM(amount) as total_claim_amount
    FROM onprem_oracle.claims.claims_history
    GROUP BY customer_id
) cl ON c.customer_id = cl.customer_id
WHERE c.region IN ('EMEA', 'APAC')
  AND p.policy_status = 'ACTIVE';

Multi-Cloud Terraform

// Terraform - Multi-Cloud Infrastructure 
# Azure Provider
provider "azurerm" {
  features {}
  subscription_id = var.azure_subscription_id
}

# AWS Provider
provider "aws" {
  region = var.aws_region
}

# Databricks on Azure
module "azure_databricks" {
  source = "./modules/azure-databricks"
  providers = { azurerm = azurerm }
  workspace_name = "insurance-analytics"
  vnet_id = module.azure_networking.vnet_id
}

# EMR on AWS
module "aws_emr" {
  source = "./modules/aws-emr"
  providers = { aws = aws }
  cluster_name = "insurance-processing"
  vpc_id = module.aws_networking.vpc_id
}

# Cross-cloud networking
module "cross_cloud_connectivity" {
  source = "./modules/hybrid-connectivity"
  azure_vnet_id = module.azure_networking.vnet_id
  aws_vpc_id = module.aws_networking.vpc_id
  direct_connect_gateway_id = var.dx_gateway_id
  express_route_circuit_id = var.er_circuit_id
}

06 Key Learnings

  • Open table formats (Delta, Iceberg) are essential for multi-cloud portability
  • Network latency between clouds requires careful data placement strategy
  • Unified governance tools must support all cloud environments
  • Federated query engines eliminate most cross-cloud data movement needs
  • ExpressRoute/Direct Connect are critical for production workloads
