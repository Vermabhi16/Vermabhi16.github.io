Data Mesh Domain-Driven Self-Service Telecom Enterprise

Enterprise Data Mesh Platform

Designed and implemented a data mesh architecture for a major telecommunications company, enabling domain teams to own and share data products while maintaining federated governance. The platform supports 15 domain teams serving 200+ data products to 3,000 consumers.

01 Business Challenge

The telecom organization struggled with a centralized data team bottleneck that couldn't keep pace with the growing demand for data products across the enterprise:

  • Central data team backlog of 200+ requests with 6-month average delivery time
  • Domain experts disconnected from data pipeline development and ownership
  • Data quality issues due to lack of domain knowledge in central team
  • Monolithic data lake becoming unmaintainable with unclear ownership
  • Inability to scale data capabilities with business growth
  • Complex dependencies between datasets slowing down changes

02 Solution Architecture

Implemented a data mesh following the four core principles: domain ownership, data as a product, self-serve data platform, and federated computational governance. Each domain operates autonomously while adhering to global standards and interoperability requirements.

03 Technical Implementation

Data Product Contract

// data-product.yaml - Data Product Specification 
apiVersion: datamesh.io/v1
kind: DataProduct
metadata:
  name: customer-360
  domain: customer
  owner: customer-data-team@telecom.com
  version: 2.1.0
spec:
  description: |
    Unified customer view combining profile, usage, and billing data
    for analytics and operational use cases.

  output_ports:
    - name: customer_360_gold
      type: delta_table
      location: unity://customer.gold.customer_360
      format: delta
      schema:
        - name: customer_id
          type: string
          description: Unique customer identifier
          pii: true
          classification: confidential
        - name: lifetime_value
          type: decimal(18,2)
          description: Calculated LTV
        - name: churn_probability
          type: float
          description: ML-predicted churn score

  sla:
    freshness: 1 hour
    availability: 99.9%
    quality_score: 95%

  quality_rules:
    - rule: customer_id_not_null
      expression: "customer_id IS NOT NULL"
      severity: critical
    - rule: ltv_positive
      expression: "lifetime_value >= 0"
      severity: warning

  dependencies:
    - product: customer.profile
      version: ">=1.0.0"
    - product: billing.transactions
      version: ">=2.0.0"
    - product: network.usage_events
      version: ">=1.5.0"

Self-Service Platform - Domain Template

// Terraform - Domain Infrastructure Template 
module "domain_platform" {
  source = "./modules/domain-platform"

  domain_name    = var.domain_name
  domain_owner   = var.domain_owner_email
  environment    = var.environment
  cost_center    = var.cost_center

  # Databricks Workspace
  databricks_config = {
    sku                  = "premium"
    enable_unity_catalog = true
    metastore_id         = data.databricks_metastore.main.id
    catalog_name         = "${var.domain_name}_catalog"
  }

  # dbt Project Bootstrap
  dbt_config = {
    project_name = "${var.domain_name}_transform"
    profile      = var.domain_name
    target       = var.environment
  }

  # Airflow DAG Folder
  airflow_config = {
    dag_folder     = "domains/${var.domain_name}/dags"
    pool_slots     = 10
    default_queue  = "${var.domain_name}-workers"
  }

  # Data Quality
  quality_config = {
    great_expectations_store = "s3://${var.quality_bucket}/${var.domain_name}"
    soda_cloud_api_key       = var.soda_api_key
  }

  # Access Controls
  access_config = {
    admin_group     = "${var.domain_name}-admins"
    developer_group = "${var.domain_name}-developers"
    consumer_group  = "${var.domain_name}-consumers"
  }
}

Policy Enforcement with OPA

// Rego - Data Mesh Governance Policies 
package datamesh.governance

# Require data product contracts for all published datasets
deny[msg] {
    input.resource_type == "data_product"
    input.action == "publish"
    not input.data_product.contract
    msg := "Data products must have a valid contract before publishing"
}

# Enforce PII handling requirements
deny[msg] {
    input.resource_type == "data_product"
    some column in input.data_product.schema
    column.pii == true
    not column.classification
    msg := sprintf("PII column '%s' must have classification label", [column.name])
}

# Require SLA definitions for production data products
deny[msg] {
    input.resource_type == "data_product"
    input.environment == "production"
    not input.data_product.sla.freshness
    msg := "Production data products must define freshness SLA"
}

# Validate schema compatibility for major version changes
deny[msg] {
    input.action == "version_upgrade"
    input.version_type == "major"
    breaking_changes := count([c | c := input.schema_changes[_]; c.breaking == true])
    breaking_changes > 0
    not input.migration_plan
    msg := sprintf("Major version with %d breaking changes requires migration plan", [breaking_changes])
}

06 Key Learnings

  • Organizational change is harder than technical change - invest in enablement
  • Start with 2-3 domains as proof of concept before scaling
  • Data contracts are essential for reliable cross-domain dependencies
  • Self-serve platform must be genuinely easy to use or adoption suffers
  • Federated governance requires clear escalation paths for exceptions
