CI/CD Pipeline for Data Engineering

Established enterprise-grade CI/CD practices for data engineering at a major energy company, implementing Infrastructure as Code, containerized workloads, automated testing, and GitOps workflows for 50+ data pipelines across development, staging, and production environments.

01 Business Challenge

The data engineering team operated with manual deployment processes that led to frequent production issues and slow delivery cycles:

  • Manual deployments causing inconsistencies between environments
  • No automated testing leading to production data quality issues
  • Infrastructure changes made through console clicks, not tracked in version control
  • 2-week deployment cycles due to manual approval and deployment processes
  • No rollback capability when issues occurred in production
  • Tribal knowledge required for deployments, creating key-person dependencies

02 Solution Architecture

Implemented a comprehensive DataOps platform with GitOps principles, automated testing at multiple levels, and Infrastructure as Code for all data platform resources.

03 Technical Implementation

GitHub Actions Workflow

// .github/workflows/dbt-ci.yml 
name: dbt CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  DBT_PROFILES_DIR: ./profiles

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: SQL Linting
        uses: sqlfluff/sqlfluff-github-actions/lint@v1
        with:
          paths: models/
          config: .sqlfluff

  test:
    needs: lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v4
        with:
          python-version: '3.10'

      - name: Install dependencies
        run: |
          pip install dbt-databricks great_expectations pytest

      - name: dbt deps
        run: dbt deps

      - name: dbt compile
        run: dbt compile --target ci
        env:
          DBT_TOKEN: ${{ secrets.DATABRICKS_TOKEN }}

      - name: Run unit tests
        run: pytest tests/unit -v

      - name: dbt test (schema tests)
        run: dbt test --target ci --select tag:unit

  deploy-staging:
    needs: test
    if: github.ref == 'refs/heads/develop'
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to Staging
        run: |
          dbt run --target staging --full-refresh
          dbt test --target staging
        env:
          DBT_TOKEN: ${{ secrets.STAGING_DBT_TOKEN }}

  deploy-production:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to Production
        run: |
          dbt run --target prod
          dbt test --target prod
        env:
          DBT_TOKEN: ${{ secrets.PROD_DBT_TOKEN }}

Terraform Infrastructure

// terraform/modules/databricks/main.tf 
terraform {
  backend "azurerm" {
    resource_group_name  = "rg-terraform-state"
    storage_account_name = "tfstateenergy"
    container_name       = "tfstate"
    key                  = "databricks.tfstate"
  }
}

module "databricks_workspace" {
  source = "./modules/databricks-workspace"

  for_each = var.environments

  workspace_name = "dbw-${var.project}-${each.key}"
  resource_group = azurerm_resource_group.main[each.key].name
  location       = var.location
  sku            = each.value.sku

  # Network configuration
  vnet_id              = module.networking[each.key].vnet_id
  private_subnet_name  = module.networking[each.key].private_subnet
  public_subnet_name   = module.networking[each.key].public_subnet

  # Unity Catalog
  metastore_id = databricks_metastore.main.id

  tags = merge(var.common_tags, {
    Environment = each.key
  })
}

resource "databricks_cluster" "shared" {
  for_each = var.environments

  cluster_name            = "shared-${each.key}"
  spark_version           = var.spark_version
  node_type_id            = each.value.node_type
  autotermination_minutes = each.value.auto_terminate

  autoscale {
    min_workers = each.value.min_workers
    max_workers = each.value.max_workers
  }

  spark_conf = {
    "spark.databricks.delta.preview.enabled" = "true"
  }
}

Docker Containerization

// Dockerfile - Airflow with custom operators 
FROM apache/airflow:2.7.0-python3.10

USER root
RUN apt-get update && apt-get install -y \
    gcc \
    python3-dev \
    && rm -rf /var/lib/apt/lists/*

USER airflow

# Install custom requirements
COPY requirements.txt /requirements.txt
RUN pip install --no-cache-dir -r /requirements.txt

# Install custom operators package
COPY dist/energy_operators-*.whl /tmp/
RUN pip install /tmp/energy_operators-*.whl

# Copy DAGs and plugins
COPY dags/ /opt/airflow/dags/
COPY plugins/ /opt/airflow/plugins/

# Health check
HEALTHCHECK --interval=30s --timeout=30s --start-period=5s --retries=3 \
    CMD ["python", "-c", "from airflow.models import DagBag; d = DagBag(); assert not d.import_errors"]

06 Key Learnings

  • Test data management is often harder than the CI/CD pipeline itself
  • Feature flags enable safe production deployments without feature branches
  • Terraform state management requires careful planning for team collaboration
  • Docker multi-stage builds significantly reduce image sizes and build times
  • GitOps with ArgoCD provides superior visibility into deployment state
